# BOSS · 任务8：本机安装（有 su 时，不用电脑）

> 需求：检测到设备已有 su 后，直接在手机上读分区 → 修补 → 写回，全程不接电脑。

## 1. 和「修补页」的分工

| | 修补页（任务7） | 本机安装（本任务） |
|---|---|---|
| 镜像来源 | 用户选文件 | 直接读 `/dev/block/by-name/` |
| 写回方式 | 导出 → fastboot | **dd 写分区** |
| 需要电脑 | 是 | 否 |
| 需要 root | 否 | **是** |
| 变砖风险 | 低（bootloader 有保护） | **高**（dd 什么保护都没有） |

## 2. root 通道：两路，缺一不可

`core/RootShell.kt`：

1. **BOSS daemon**（`BossIpc.exec`）——已安装时的首选，有授权弹窗与审计
2. **系统 su** —— 逐个试 `/data/adb/ksu/bin/su`、`/system/bin/su`、`/sbin/su` …

⚠️ **退回这一路才是本功能的意义所在**：本机安装最该有用的场景恰恰是
**BOSS 还没装的时候**——那时没有 daemon，唯一能用的就是设备上已有的 su。
少这一路，功能就在它最该生效的场景失效。

> ⚠️ 直接 `exec` 系统 su 这条路**未上真机验证**：App 是 untrusted_app，
> 能否 fork/exec 某个 su 取决于那个 su 的路径权限与 SELinux 策略，
> 各 root 方案差别很大。所以是逐个探测，不假定某一个一定在。

## 3. 五道闸（写回前逐条过）

`LocalInstallRepository.preflight()`。**任何一道不过就不写。**

| # | 检查 | 防的是什么 |
|---|---|---|
| ① | 写回目标 = 读出来的那个路径（同一字符串） | 重新探测可能因槽位变化指向另一个分区 |
| ② | magic 是 `ANDROID!` / `VNDRBOOT` | veritpath 产出垃圾时的最后一道网 |
| ③ | 产物 ≤ 分区大小 | dd 写超长被截断 → 开机必死 |
| ④ | `veritpath verify` 通过 | 镜像不完整 |
| ⑤ | 备份存在且非空 | 没有退路就不动手 |

设计初衷一致：**宁可不动，也不能动错。**

## 4. 三个刻意的设计

### ① 备份永不自动删除

`dump()` 里如果备份已存在就复用，不覆盖。
万一第一次修补写坏了，用户第二次进来还能拿到**最初**那份。
覆盖掉等于把唯一的退路抹了。

### ② 分步执行，不做一键安装

`LocalInstallViewModel` 刻意做成三步单独点。
一键到底的脚本在变砖场景下是最糟的设计——
既不知道断在哪，也没有机会在写分区之前喊停。

### ③ 不做"回读校验"

写完之后再读回来对比必然相同，那是自欺欺人，
反而给出虚假的安全感。真正有意义的校验全在写之前做完了。
写完之后唯一诚实的说法就是：**请重启验证**。

## 5. 还加了两个防呆

- **磁盘空间**：`/data` 剩余 < 分区大小 × 3 就不开始。
  dd 写一半失败会留下**损坏的备份**，比不备份更糟。
- **跳过 ① 直接 ②**：修补时若工作副本不存在就报错，
  不偷偷补做 dump——否则用户没备份也能走到写回。

## 6. 验证状态（诚实版）

| 项 | 状态 |
|---|---|
| C 侧回归（IPC / manager / 契约 / 上游四套） | ✅ 全绿 |
| Kotlin 静态检查（顶层类型 import、括号平衡） | ✅ 通过 |
| **Gradle 编译** | ❌ 未验（沙盒无 SDK） |
| **真机 exec 第三方 su** | ❌ 未验 |
| **真机 dd 写分区** | ❌ **未验，且这是本任务唯一真正重要的验证** |

⚠️ **强烈建议第一次用 PC + fastboot 走一遍**（`docs/真机首测-runbook.md`），
确认镜像本身没问题之后，再用本机安装做"OTA 后重新修补"这类场景。
本机 dd 写分区一旦出错，唯一的自救就是那份备份。

## 7. 用法

App → 「本机安装」tab：

```
0 · 前置      探测 root 与分区（自动）
1 · payload   选解压后的 payload 目录
2 · 分步      ① 读出分区（＝备份） → ② 修补 + 自检
3 · 写回      勾选确认 → 写回分区（红按钮）
              出问题 → 还原原厂分区
```

重启后验证：`ls -l /proc/1/exe` 指向 boss = 成功。
